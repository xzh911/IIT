## 4. dev 面板现状与改进（用户在等这个）

**现状**：已有「JSON 覆盖层编辑器」——任何接口响应都能手写编辑、保存、刷新生效（localStorage）；但没有表单化编辑。
**改进方案**（V2，可交付）：
1. 「一键生成的模板」改为「**模板 + 表单编辑**」：选中模板后在同一面板展示该模拟数据的字段表单（姓名/金额/日期…），改完自动写覆盖层。
2. **通用字段编辑器**：任一路由可展开编辑 data 的每个字段（字符串/数字/数组自动识别），替代手写 JSON——这是主要工作量，需设计 schema 推导（从现有 fixture JSON 推断字段类型即可）。
3. 保留 JSON 原始编辑 + 复制持久化。

## 6. 真能做完吗？—— 诚实回答

**能做完的含义**：真机能装、打开无黑屏、主要 tab 能走、核心业务流程（收入明细→纳税记录→完税证明→申报）闭环有数据、dev 面板可改数据 —— **这个可以做到，约 2 周**。
**做不完的部分**：① 50+ 页的完整铺开（取决于预算，属加菜不是主菜）；② 与官方未来版本的实时同步（官方一变就失效）；③ 像素级逐页完美（真机渲染差异永远存在，规则 §2 允许记录差异而不硬追）。
**风险提醒**：唯二的硬风险 = ① IPA 在 SideStore/iloader 上装不上（若出现，需转自签另一路径，属环境问题不是代码问题）；② 官方动态策略更新导致 fixture 参考失效（可能性中等，但每次都只是「换 fixture」）。

**建议验收定义**：装好「个人所得税」App → 首页 5 秒内有内容 → 5 个 tab 可切换 → 4 条核心业务链路走通（含 mock 数据可编辑）→ 无「很抱歉」阻断 → 即视为 V1 收官。达成后进入优化轮或封版。
